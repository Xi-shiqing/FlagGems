# PPU 长求和 MM：分段并行与段内流水

`FLAG_GEMS_PPU_LONG_MM_SPLIT=1` 启用候选实现。当前默认值为 `0`，完整实验记录位于 Protenix 的 `comparison/mm_parallel_serial_20261109/`。

计算 `C=A@B` 时，长求和方向 K 划分为多段。不同段同时计算，每段内部顺序累加，并用三级流水提前读取后续输入。各段结果分别写入临时数组，再按固定段号顺序合并，没有浮点原子加法。

这里包含两层并行：输出的不同区域可以同时计算，同一区域的不同 K 段也可以同时计算。段内继续顺序累加，控制临时内存和同步开销。

候选沿用已有长求和路径的输入范围：FP32 存储，左输入按列连续、右输入按行连续，K 大于 8192，输出两维在 32 至 1024 之间，原有 32×32 输出块数不超过计算单元数的四倍。实际计算改用 64×64 输出块以提高输入复用。

分段数依据两个要求选择：至少提供约四倍计算单元数的任务，以及尽量将每段串行求和长度控制在 8192 以内；然后限制最多 64 段、每段至少约 128 个输入、临时数组最多 64 MiB。没有模型名称、输入编号或已测尺寸查找表。

实现还支持一个任务顺序计算多个逻辑分段。实验发现这一安排没有稳定收益，当前选择各段独立执行。所有逻辑分段仍单独保存，切换任务安排不会重新组织最终加法顺序。

FP32 使用严格 FP32 点积；TF32 保留已有输入舍入方式，并使用调用方传入的模块精度设置。改变分段边界会改变累加舍入，因此实验分别检查固定分段方案的逐位一致性，以及新分段相对 FP64 和已有 H100 结果的误差。真实训练还检查完整梯度和实际参数更新。

2026-11-09 的完整训练复测使用 Protenix-v2、实际 600 token 输入、统一随机数和相同初始参数。同卡四次交替运行的第二步中位耗时：FP32 从 134.976 秒降到 117.358 秒，TF32 从 85.127 秒降到 74.239 秒；分别下降 13.05% 和 12.79%。仓库实际入口另行复测通过。43 项接口测试与实际自动求导检查通过。

完整训练梯度相对已有 H100 的 L2 差异：FP32 从 0.0018066% 降至 0.0017834%，TF32 从 0.7740924% 升至 0.7771090%。实际更新差异分别从 0.0528962% 降至 0.0528452%、从 4.4562238% 升至 4.4625386%。因此当前保留为可选实现。Tiny、Mini ESM 的三组完整推理共 120 次预测，坐标和五项置信度在开关前后逐位一致；这三组的长求和新路径调用次数均为零。
