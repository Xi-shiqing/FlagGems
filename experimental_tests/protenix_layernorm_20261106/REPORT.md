# LayerNorm 反向检查与 FlagGems 通用优化

日期：2026-11-06。

本轮新增了真实融合 LayerNorm 的完整反向检查，修正了 FlagGems 通用接口的归一化维度划分，并实现输入梯度与参数梯度的融合计算。融合版在已测大输入上快于模型当前 C++ 实现；小输入保留 C++ 路径。

## 实际发现与实现

LayerNorm 接收输入、传入梯度、保存的均值/倒标准差及仿射参数，返回输入梯度、缩放参数梯度和偏置参数梯度。先重放原 MSA0 三个子模块、两个实际 batch，在两种模型精度下各做观察及未观察两遍；输出和全部参数梯度恢复原记录。

原 FlagGems 反向把输入第一维当作外部行数。例如输入 [2,3,7]、normalized_shape=[7]，正确划分是 6 行、每行 7 项；原实现却得到 2 行、每行 21 项，后续参数梯度的写入宽度也随之错误。修正后按 normalized_shape 的元素数确定行宽，并处理空输入。模型原来的 C++ LayerNorm 绕过这个通用入口。

仅修正维度后，长轴参数梯度仍由少量任务长时间求和。分段版增加并行任务，最多 256 份部分和，临时存储上限 64 MiB，再按固定树形归并。融合版进一步在同一输入块内计算三类梯度，减少重复读取。行块大小按归一化宽度确定，单块最多 2048 个元素；接入规则使用行数、行宽、数据类型及资源上限，没有模型、层名、输入名或精确形状名单。

## 真实两步训练与采用决定

沿用原配置、实际 batch、初始权重和统一随机数，FP32、TF32 各训练两步。第 0 步学习率为 0 并更新 Adam 状态；第 1 步学习率为 1.8e-5 并实际更新参数。比较覆盖全部 4170 份梯度、464441841 个梯度元素，以及 4174 份实际更新。

| 指标 | PPU + FlagGems FP32 | H100 原生 FP32 | PPU + FlagGems TF32 | H100 原生 TF32 |
|---|---:|---:|---:|---:|
| 新方案第 0 步 loss | 1.879857898 | 1.879856706 | 1.883392215 | 1.882853270 |
| 新方案第 1 步 loss | 4.581814766 | 4.581809044 | 4.578239441 | 4.579020500 |
| 原路径：完整梯度差异 / % | 0.001540360 | 0（参考） | 1.289788063 | 0（参考） |
| 新路径：完整梯度差异 / % | 0.001729641 | 0（参考） | 1.306005377 | 0（参考） |
| 原路径：实际更新差异 / % | 0.042941142 | 0（参考） | 6.433917284 | 0（参考） |
| 新路径：实际更新差异 / % | 0.042364647 | 0（参考） | 6.369522523 | 0（参考） |

至少一项完整梯度或实际更新对 H100 的差异增加，未通过预先约定的训练路径提名条件；默认训练路径保持原版本。

两种精度各有 1294 次实际反向调用进入注册的 FlagGems 融合分支，另 480 次保留 C++。训练输入、初始权重、有序随机数和学习率审计结果均在完整训练比较文件中。H100 数值复用已有缓存。新训练运行含编译与检查过程，未据此申报正式整网速度或 MFU 收益。

这轮结果将后续设计约束收紧到反向传播的数值保持：融合确实减少了访存，但输入梯度的求和、乘法结合顺序发生变化，会继续传入其余模块。下一项方案先要求实际输入梯度与原路径逐字节一致，再检查其余融合和参数求和；仅减少局部数学误差不能作为接入整网的条件。

## 覆盖与证据

- 最后算子验证包含 8 组形状/布局、4 种仿射组合及梯度掩码，共 128 次检查（含重复掩码），另查空外部行。
- 注册接口检查通过 6 组正尺寸输入（含多维归一化、非标准前缀和大行宽）及 2 组空输入；使用真正的 PyTorch 自动求导及注册反向入口。
- 最后重放 16 份实际接口数据，四种实现均保存全部三类梯度的误差和七次计时样本。
- 首轮捕获大尺寸全零上游的记录保留；补充捕获同时保存每类接口首个零及非零调用。全部模块校准保留，未替换现场梯度。
- 首次新核编译的别名错误、首次注册检查的 include 名称错误均保留在失败文件中，修正后使用新源码和新输出目录。
