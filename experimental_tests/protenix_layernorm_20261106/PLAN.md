# 2026-11-06：融合 LayerNorm 的实际反向与误差传播

昨天的分组 MM 改善了局部 TF32 速度和误差，但两步整网梯度差异未改善。历史记录已经否决全模块升精度、单独修改注意力修正项、全 TriAttention RTZ 兼容及若干梯度高精度方案，本轮不重复这些组合。

新增检查针对已有逐算子清单尚未展开的融合 LayerNorm：从真实模块重放中捕获 C++ 扩展实际收到的输入、上游梯度、保存均值/倒标准差、仿射参数，以及全部三个反向输出。

1. 复用原 PPU 229、原训练容器和已有融合 Softmax FlagGems 包。先以原 MSA0 的三个子模块、两个真实 batch，在 FP32/TF32 各执行观察及未观察两遍。完整模块输出、参数梯度和重复结果须恢复已有记录；恢复保存的有序随机状态。
2. 所有融合 LayerNorm 调用登记签名。每个 step/归一化维度/仿射接口选择首次调用，保存完整 ABI 操作数及结果，最多 12 GiB/精度；选择规则用于诊断捕获。
3. 直接重放保存 ABI，核对完整输出逐字节恢复、输入不变和重复一致。以保存 mean/rstd 的 CPU64 解析式检查 dX/dGamma/dBeta，并另算重算统计量的参考，分开统计量误差与反向运算误差。公式先用非退化小例与 CPU64 autograd 核对。
4. 按相同向量范数汇总，不以参数梯度的大跨设备差异认定 LayerNorm 本身有故障。若存在明显局部误差或性能缺陷，针对共同数学规则实现候选，再做全部捕获调用及真实训练验证；没有明确原因时不盲目改内核。

只在 PPU 新执行。H100 复用既有结果；没有这批相同 ABI 输入的 H100 数值则留空。原始张量留原服务器。候选不改变模型、标签、优化器、学习率、随机数或验收门槛。

首轮捕获完成后发现，首个 256 维 LayerNorm 的传入梯度全为零。保留这些零值结果，第二轮按 `(step, normalized_shape, affine_interface, dy_nonzero)` 各保存首次调用，以同时保留零和非零的实际调用；选择规则修正见 `nonzero_capture_correction.json`。零输出不能用于判断非零梯度的精度。两轮完整模块校准都保留。

源码检查还发现通用 FlagGems LayerNorm 反向将 M 取为 `input.shape[0]`，没有沿 `normalized_shape` 正确划分外部行；Protenix 当前 C++ 接口绕过了这个入口。新增独立算子候选修正该维度语义，并把长外部行求和分段后合并，以增加并行任务。先检查公共接口、多维输入、尾部及梯度掩码，再测实际 ABI 数据。性能对照使用仅修正维度的原实现，原错误接口不在可能越界的三维输入上运行。

分段版比旧 FlagGems 快，但实际大输入仍慢于当前 C++。因此增加单次读入时同时计算输入梯度与仿射参数部分和的融合版本；输出按固定树形归并。小输入继续走当前 C++，大输入仅按行数、归一化宽度、FP32 类型和资源上限接入，不使用模型名或精确形状表。

融合版完成算子及注册入口检查后，按原配置各做两步 FP32、TF32 训练。原学习率计划保持：第 0 步为 0 并更新 Adam，第 1 步为 1.8e-5。核对全部初始参数、实际 batch、3338 项有序随机数、loss 分项、完整 4170 份梯度、4174 份实际更新及 Adam 状态。提名为默认训练路径的条件是两种精度下完整梯度及实际更新对既有同精度 H100 的相对 L2 差异均不增加；不满足时保留实验结果，默认训练路径不更换。算子性能按同卡 GPU 事件计时比较，整网新编译过程不计作正式训练吞吐收益。
