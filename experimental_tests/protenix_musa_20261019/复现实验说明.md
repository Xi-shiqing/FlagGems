# 复现实验说明

报告阶段统一为2026年10月14日至18日。实际测量日志包含18日至19日的记录，补测及质量复核在19日完成；原始时间戳保留，不以报告阶段替代机器记录。

## 一、先复算已有结果

在本目录运行：

```bash
python3 verify_results.py
```

只需要Python标准库。脚本从逐次记录重新核对耗时中位数、活跃显存峰值、主实验与多种子质量均值、交替复测、四种存储策略、H100参照和调用次数。它不运行模型，也不重新计算结构质量。公开包不包含原始结构和固定特征，因此不能仅靠此目录独立重建完全相同的模型输入。

## 二、重新运行模型需要什么

需要MTT S5000及兼容的MUSA环境、已有Protenix源码部署、`protenix_base_default_v1.0.0`权重、输入JSON及MSA，以及经授权使用的固定CPU特征。版本和模型摘要见`environment.json`。模型主干源码及权重应与记录核对；相同文件名不代表版本一致。

原实验使用Python 3.10.12、PyTorch 2.7.1、torch_musa 2.7.1（实测运行标记含`+d212062`）与Triton 3.2.0。公开脚本不会自动安装、更新或删除环境。推理仍使用原部署的`env.sh`设置Python和模型数据路径。

将输入放在本目录的`inputs/<名称>.json`，对应固定特征放在`frozen_features/seed_<种子>/<名称>.pt.gz`。没有原始冻结输入时，应对自己的输入重新准备并记录摘要；这种新实验不能直接沿用旧记录的输入一致性结论。输入、MSA、权重和结构不随本次提交公开。

## 三、原生与混合方案配对运行

以下是可迁移路径的公开启动方式。`PTX_MUSA_HOME`指向已部署的Protenix环境，`PTX_GPU`应由运行者选择空闲的容器可见显卡。两个版本使用同一张卡，分别新建进程执行，模式名称选用未使用的值以避免覆盖旧结果。

```bash
export PTX_MUSA_HOME=/path/to/existing/protenix_musa_deployment
export PTX_GPU=0
export INPUT_NAME=7b8b
export BENCH_SEED=101
export BENCH_REPEATS=6

EXPERIMENT_MODE=recheck_native FUSION_POLICY=inplace FROZEN_MODE=read \
  bash run_worker.sh

EXPERIMENT_MODE=recheck_hybrid FUSION_POLICY=hybrid FROZEN_MODE=read \
  bash run_worker.sh
```

原生模式名称不能含`fused`，该词会启用原地融合。混合路径由`FUSION_POLICY=hybrid`启用。公开启动脚本保持主干BF16、扩散和置信度FP32张量、允许TF32，以及10轮循环、200步扩散和5个候选结构。大于1024 tokens时，两版都在主干循环边界同步。`env.sh`应正确设置所选MUSA设备和Python依赖；原脚本中的宿主GPU映射仅适用于原实验容器，其他机器须自行核对，不能照搬。

此启动脚本只将个人部署路径改为环境变量；打包阶段通过语法检查，未重新进行GPU实验。核心测量及融合Python文件保持原实验字节，摘要见`source_provenance.json`。不要将新启动脚本的检查称作新增硬件验证。

## 四、其他验证入口

- `ablation_benchmark.py`：8种尺寸×2种精度×2种布局×5个版本，共160个合成场景。
- `crossover_hybrid.py`：同一已加载模型中交替执行两版，各8次正式测量。通过`BENCHMARK_ENTRY`选择该入口，并保持相同冻结输入。
- `storage_crossover.py`：比较原生、原地、独立输出和混合四种路径，每条6次。
- `quality_selfcheck.py`：参考结构与固定扰动结构的PXMeter自检，需要另行配置参考结构和评估工具路径。
- `triangle_safe.py`、`packed_adaln.py`与`packed_transition.py`：保留的候选实现，不是最终主实验的默认路径。
- `plot_research.py`：使用归档的统计数据重绘图表，需要Matplotlib和NumPy；原绘图脚本输出到`图表/`，本次公开归档将图片平铺保存。

质量使用PXMeter 1.1.1，Biotite 1.2.0。原评估环境将兼容导入改为公共的`biotite.structure.concatenate`，并用正对照及固定扰动参考结构核验。原始生成索引0与最终排名第一结构应分别评估。结构质量的重新计算需要原始坐标和参考结构，公开包中的指标记录不能替代这一计算。

## 五、结果范围

主实验仅使用`final_native`与`final_hybrid`。其他目录或模式保留探索、旧精度路径及验证记录，不能从不同组里拼接最快结果。结构质量以正式对照CSV的`quality_screen`为准，`quality.json`中的工具PASS仅表示评估执行成功。

本目录用于实验成果归档，未将算子注册到FlagGems默认执行路径，也未验证训练收益或其他芯片上的通用加速。
